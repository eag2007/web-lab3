## Описание

Веб-приложение проверяет попадание точки в область на координатной плоскости. Координаты задаются в форме или двойным нажатием на график. Проверка выполняется на сервере; результаты хранятся в Bean-компоненте в HTTP-сессии и выводятся в таблицу и на график.

Приложение построено по MVC с использованием сервлетов и JSP. Данные для проверки отправляются методом `POST`.

## Архитектура

```text
Браузер → ControllerServlet → AreaCheckServlet → AreaChecker
                  │                    │
                  │                    ├── ResultsBean в HTTP-сессии
                  │                    └── result.jsp → результат
                  └── form.jsp → форма, график и история
```

| Компонент | Назначение |
|---|---|
| `ControllerServlet` | Принимает запросы, показывает форму или передаёт данные на проверку |
| `AreaCheckServlet` | Получает X, Y и R, проверяет данные и сохраняет результат |
| `AreaChecker` | Определяет попадание точки в область |
| `CheckResult` | Хранит X, Y, R и результат одной проверки |
| `ResultsBean` | Хранит список результатов в сессии |
| `form.jsp` | Формирует страницу с формой, графиком и историей |
| `result.jsp` | Показывает результат проверки и ссылку на форму |
| WildFly | Запускает веб-приложение, сервлеты и JSP |

Запросы между сервлетами и JSP передаются внутри сервера через `forward`. Приложение работает в standalone-конфигурации WildFly.

## Запросы

| Метод и адрес | Назначение |
|---|---|
| `GET /controller` | Открыть страницу формы |
| `POST /controller` с X, Y и R | Проверить точку и открыть страницу результата |
| `POST /controller` без параметров точки | Открыть страницу формы |

Адреса указаны относительно контекстного пути приложения. Например: `/web-lab3/controller`. Проверка точки выполняется на сервере; `AreaCheckServlet` вызывается через контроллер.

## Входные данные

| Параметр | Ввод в форме |
|---|---|
| X | Select: `-2`, `-1.5`, `-1`, `-0.5`, `0`, `0.5`, `1`, `1.5`, `2` |
| Y | Текстовое поле: число больше `-5` и меньше `3` |
| R | Radio: `1`, `2`, `3`, `4`, `5` |

При двойном нажатии на график X и Y вычисляются по положению курсора. Для отправки точки с графика необходимо выбрать R. JavaScript проверяет данные формы; сервер дополнительно проверяет формат чисел, их конечность и значение R.

## Область

Точка считается попавшей, если она принадлежит хотя бы одной фигуре. Границы включены.

| Фигура | Условие |
|---|---|
| Четверть круга слева сверху | `x ≤ 0`, `y ≥ 0`, `x² + y² ≤ R²` |
| Квадрат слева снизу | `−R ≤ x ≤ 0`, `−R ≤ y ≤ 0` |
| Треугольник справа сверху | `x ≥ 0`, `y ≥ 0`, `x + y ≤ R/2` |

## Функциональность

- Проверка точки из формы или двойным нажатием на график.
- Масштабирование координат и подписей графика при изменении R.
- Отображение истории проверок и сохранённых точек на графике.
- Отдельная страница результата с параметрами и ссылкой обратно к форме.
- Изображение и случайный анекдот на странице результата.
- Адаптивная тёмная тема.

История хранится в HTTP-сессии: при её завершении данные могут быть потеряны. Цвет точки соответствует результату исходной проверки.

## Запуск

### Требования

- JDK 21;
- WildFly 35;
- доступ к репозиториям Gradle для первоначальной загрузки зависимостей.

Примеры рассчитаны на Linux и запуск из корня проекта. При других путях или имени WAR замените их в командах.

### Сборка

```bash
cd ~/IdeaProjects/web-lab3
```

```bash
JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 ./gradlew clean war
```

WAR появится в `build/libs/`. Если Gradle Wrapper не исполняется, выполните `chmod +x gradlew`.

### Развёртывание

Скопируйте архив в каталог развёртывания WildFly:

```bash
cp -f build/libs/web-lab3-1.0-SNAPSHOT.war ~/wildfly-35.0.0.Final/standalone/deployments/web-lab3.war
```

Запустите сервер:

```bash
JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 ~/wildfly-35.0.0.Final/bin/standalone.sh -b 0.0.0.0
```

Откройте [http://localhost:8080/web-lab3/controller](http://localhost:8080/web-lab3/controller). Для остановки нажмите `Ctrl+C` в терминале WildFly.

### Порты

В примере используется стандартный HTTP-порт `8080`. Для сдачи порты необходимо настроить в соответствии с выданным `portbase`; параметр запуска `-b 0.0.0.0` задаёт прослушивание публичного интерфейса на всех IP.

### После изменения кода

Остановите WildFly, повторите сборку и копирование WAR, затем запустите сервер. Если браузер показывает старые CSS или JavaScript, обновите страницу с помощью `Ctrl+Shift+R`.

### Если приложение не открывается

| Проблема | Что проверить |
|---|---|
| `BUILD FAILED` | Сообщение Gradle, JDK и доступность зависимостей |
| `UnsupportedClassVersionError` | Версии JDK сборки и запуска WildFly |
| `404` | Сообщение о развёртывании, имя WAR и URL с контекстным путём |
| Ошибка развёртывания | Логи WildFly и файл `web-lab3.war.failed` в `standalone/deployments/` |
